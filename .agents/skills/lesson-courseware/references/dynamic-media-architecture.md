# 动态媒体与微课视频扩展架构规范 (dynamic-media-architecture.md)

> 本文件是教师 PPT 课件生成系统从「静态课件」扩展至「动态演示与微课视频」的权威架构参考与演进规范。
> 任何 AI Agent 或工程开发者在实现多媒体、动态动画或微课生成功能时，必须严格遵守本文件定义的边界与原则。

---

## 一、核心定位与五大工程底线

动态媒体引擎是课件生成系统的**受控子模块**，旨在为课堂教学提供直观的重难点动态演示，以及为课后提供基于教参讲稿的音画同步复习微课。

为确保教育教学的严谨性、系统稳定性与代码安全性，工程实施必须严守以下五条底线：

### 1. 内容正确优先于渲染精确（否定“零幻觉”假设）
* **底线原则**：动画引擎（无论 Canvas 还是视频渲染器）只负责执行几何与视觉渲染，无法判断教学内容真伪。若输入错误的数学角度（如要求 $60^\circ$ 却传入 $80^\circ$），引擎只会“极其精确地画出错误”。
* **执行规范**：严格执行前置门禁：
  $$\text{教材只读事实源} \longrightarrow \text{数学逻辑与数域校验} \longrightarrow \text{声明式参数生成} \longrightarrow \text{确定性执行渲染}$$
  动画引擎只接收经过质量门禁 100% 校验合格的参数，绝不内嵌任何自行推断的教学逻辑。

### 2. 严禁 AI 动态执行任意代码（Arbitrary Code Execution）
* **底线原则**：严禁让大模型直接编写可执行的 JavaScript/Python 动画代码。任意代码会导致无法执行、视口越界、沙箱安全漏洞、测试黑盒与维护灾难。
* **执行规范**：全面采用**声明式组件参数模型 (Declarative DSL)**。AI 仅负责输出结构化参数 JSON，由系统预置的、经过完备单测覆盖的确定性动画组件库解析执行。

### 3. 技术栈极简收敛，拒绝多引擎依赖膨胀
* **底线原则**：不把 Manim、Remotion、扩散模型等技术重叠的框架同时引入作为核心依赖，避免项目依赖膨胀与环境脆弱。
* **执行规范**：紧密围绕项目现有的**纯 JavaScript / Node.js 全栈生态**。优先利用 PPT 原生矢量形状与分步呈现；后续独立微课渲染收敛于统一的 JavaScript 技术栈（如基于 SVG/Canvas 或轻量 Remotion），绝不回退引入 Python/LaTeX/C 混合编译重链条。

### 4. 互动教学回归跨平台 100% 可靠的“状态机分支”
* **底线原则**：不依赖特定 PPT 播放器的私有黑魔法（如视频播放到特定秒数自动暂停并弹窗）。此类黑魔法在不同教室硬件（Office、WPS、希沃、鸿合大屏）表现极不一致。
* **执行规范**：将课堂互动严格定义为**页面级别的状态跳转机**：
  $$\text{[视频/情境呈现页]} \longrightarrow \text{[随堂互动选择页]} \xrightarrow[\text{选错}]{\text{选对}} \begin{cases} \text{[正解推进与鼓励页]} \\ \text{[易错点针对性剖析页]} \end{cases}$$
  采用通用的动作超链接（Hyperlink）组织页面跳转，保证教师课堂把控从容、跨平台 100% 稳定。

### 5. 严格区分产品形态与交付边界
必须区分三种不同教育场景的交付物，不搞一刀切：
* **课堂授课 PPTX**：以教师现场讲授为主控，支持逐步板书、提问与放映控制；
* **过程动态演示微件 (Component)**：专用于突破某一特定数学/科学重难点（如几何折叠、平移旋转），短小精炼、支持反复暂停重放；
* **课后复习微课 (MP4)**：将 PPT 画面与教师讲稿 `notes` 通过 TTS 对齐合成的自动化视频，面向学生自主复习。

## 二、系统架构与流水线全景

动态媒体引擎作为课件系统的子引擎，保持现有的四层物理隔离体系不被破坏：

```
1. 教材知识库 (plugin/knowledge/)
   └── 只读事实源：教材原文 · 知识点白名单 · 教学边界 · 数域上界
        ↓
2. 教学设计与契约 AST (courseware.json)
   ├── 页面结构：cover / objectives / concept / example / practice ...
   ├── 媒体声明：声明式 media / animation 参数（受统一 Schema 约束）
   └── 教师讲稿：notes（标准授课台词与提问台本）
        ↓
3. 统一质量门禁 (validate_courseware.js)
   ├── Tier 1: 结构 Schema 与必填项校验
   ├── Tier 2: 知识点归属白名单校验
   ├── Tier 3: 数学过程验证、数域上界拦截与媒体参数核验
        ↓
4. 双轨确定性渲染引擎
   ├── [主轨] PPTX 确定性渲染器 (render_deck.js / lib_js/)
   │    └── 原生文本框、卡片组件、矢量图元、页面状态跳转
   └── [子引擎] 动态媒体引擎 (Media Sub-engine，按需调用)
        └── 确定性动画组件库 (SVG/Canvas) + 讲稿 TTS 音画对齐管线
        ↓
5. 交付产物
   ├── 课堂授课课件：<标题>.pptx (主交付物，可内嵌媒体)
   ├── 动态演示微件：output/media/<演示名>.mp4 / .svg (独立过程微件)
   └── 课后复习微课：output/video/<标题>_微课.mp4 (音画同步微课)
```

## 三、声明式动画参数契约 (DSL 规范)

在课件 JSON 的页面 `figure` 属性中，扩展声明式动画定义：

### 1. 通用媒体与动画图元规范
```json
{
  "kind": "animation",
  "animation_type": "number_line_jump",
  "title": "【操作演示】用数轴理解乘法累加",
  "duration_sec": 6,
  "prompt": "观察小兔每次跳跃的格数与总共跳跃的次数",
  "parameters": {
    "start": 0,
    "step": 1,
    "jumps": [2, 2, 2],
    "target": 6
  }
}
```

### 2. 常见核心数学动画组件参数规范 (白名单制)
* **数轴累加与乘法模型 (`number_line_jump`)**：
  * `parameters.start` (整数，起点)
  * `parameters.step` (整数，单格步长)
  * `parameters.jumps` (整数数组，每次跳跃步长，如 `[3, 3, 3, 3]`)
  * `parameters.target` (整数，终点，必须等于 `start + sum(jumps)`)
* **竖式进位/退位动态推演 (`vertical_calc_flow`)**：
  * `parameters.operand_a`、`parameters.operand_b`、`parameters.operator`
  * `parameters.steps` (推演阶段序列：个位相加 -> 满十进一 -> 十位相加)
* **几何图形折叠与对称 (`fraction_fold`)**：
  * `parameters.shape` (`rectangle` | `square` | `circle`)
  * `parameters.axis` (`vertical` | `horizontal` | `diagonal`)
  * `parameters.fold_count` (折叠次数，如 1 表示对折一半，体现 $\frac{1}{2}$)

## 四、三阶段演进路线

项目严格遵循“地基先立、分步演进”的原则，避免因过度设计拉垮核心系统：

```
Phase 1: 静态 PPT 基石 (当前状态)
  • 16:9 现代宽屏卡片式排版与防近视字号
  • 原生矢量图元 (竖式、数轴、田字格、词卡、计数器)
  • 完善的教材事实源与确定性门禁校验
  • 基础 media 占位卡片与本地文件原生内嵌支持
  ↓
Phase 2: 动态媒体子引擎孵化
  • 确立固定动画组件库 (以纯 JS/SVG/Canvas 驱动)
  • 实现 3 个最核心数学操作演示组件 (数轴跳跃、几何对折、竖式流)
  • 动画参数门禁校验器 (验证数学过程与参数合法性)
  • 导出独立的 1080P 高清演示 MP4 并无缝嵌入 PPT
  ↓
Phase 3: 课后微课与音画同步
  • 基于课件 notes 教师讲稿，接入轻量 TTS 语音合成
  • 幻灯片画面推进与讲解音频时间轴自动对齐
  • 输出面向学生课后自主复习的完整微课视频
  • 基于页面状态机组织多分支课堂互动测验
```

## 五、维护纪律
1. **禁止越权**：动态媒体的任何扩充不得修改 `plugin/knowledge/` 教材事实库；
2. **零外挂脚本**：动画渲染必须在受控沙箱或预设组件库内运行，不得执行未受管辖的动态代码；
3. **保持同步**：修改本规范后，执行 `node scripts/install_skill.js` 确保 `.agents/` 目录与正本零漂移。
